1. `CC = gcc`：定义变量 CC，编译器选用 gcc。后面用 `$(CC)` 引用。
2. `CFLAGS`:编译参数
3. `-Wall`：开启大部分警告
4. `-Wextra`：开启额外警告，方便找 bug
5. `-Iinclude`：头文件搜索路径，去 `include/` 文件夹找 `.h` 头文件
6. 
- `calculator`：目标（最终程序）
- 冒号后面是**依赖**：想要生成 calculator，必须先有这3个 `.o` 文件
- 命令：链接所有目标文件，输出可执行文件 `calculator`
7. 
- 目标 `main.o`，依赖源码 `src/main.c` 和两个头文件
- `-c`：compile-only，**只编译，不链接**，生成目标文件 main.o
8. 
- `.PHONY` 伪目标用于 clean
- make 会自动比对文件修改时间，增量编译（只编译改动的部分）

9. `add_executable`：CMake 的内置命令，作用：**告诉 CMake 构建一个可执行程序**
10. `PRIVATE`：这个头文件目录只在编译本目标时生效，不会暴露给其他依赖它的项目
11. `target_include_directories(...)`:给指定**目标（这里就是 calculator 这个可执行程序）**添加头文件搜索目录。相当于 gcc 的 `-Iinclude`，告诉编译器：去 `include/` 文件夹找 `.h` 头文件。

12. 
### `.c`、`.o` 和最终可执行文件分别是什么？

- **`.c` 文件**：C 语言**源代码文件**，是我们写的文本代码，人能看懂，编译器原始输入。
- **`.o`（目标文件 object file）**：源码经过编译（`gcc -c`）后生成的二进制机器码文件。里面是翻译好的机器指令，但**函数引用地址还没补齐，不能直接运行**。
- **可执行文件**：把多个 `.o` 文件 + 系统库，经过链接合并之后得到的二进制程序，可以在操作系统直接运行（`./calculator`）。

---

### 2. 编译和链接有什么区别？

- **编译**：把**单个 `.c` 源文件**翻译成 `.o` 目标文件。只做语法检查、翻译成机器码；**不处理跨文件的函数调用**。对应 gcc `-c`。
- **链接**：把一个或多个 `.o` 目标文件 + 系统库文件合并，**解析函数符号、补齐地址**，组装成完整可执行程序。

> 
> 简单记：编译：单文件转.o；链接：多个.o 拼起来生成可执行文件。

---

### 3. 为什么 Make 能做到增量构建？

Make 会**比对文件的修改时间戳**：当执行 `make` 时：

1. 对比目标文件（比如 `calculator` / `main.o`）和它的依赖文件（`.c`/`.h`）的修改时间；
2. 如果**依赖文件比目标文件新（改动过）**，就重新执行规则，重新编译；
3. 如果依赖文件没有改动，就跳过这条规则，不重复编译。只重新编译改动相关的部分，这就是增量构建，节省编译时间。

---

### 4. CMake 是编译器吗？

**不是！**CMake 是**构建系统生成工具（元构建工具）**，**不是编译器**。编译器（gcc/clang）才负责把 C 代码翻译成机器码。CMake 的工作：读取 `CMakeLists.txt`，自动生成 Makefile（或者 Ninja 构建脚本），然后调用 make /ninja，再调用 gcc 去编译代码。

---

### 5. CMakeLists.txt 最后是怎么变成一个真正可以运行的程序的？

整套流程：

1. `cmake -S . -B build`：读取`CMakeLists.txt`，解析项目信息，在 build 目录生成 Makefile 等构建脚本；
2. `cmake --build build`：调用 make 工具，读取生成好的 Makefile，自动调用 gcc，执行**编译 + 链接**；
   - 编译：`.c` → `.o`目标文件
   - 链接：所有`.o`合并 → 可执行程序
3. 最后在 build 目录得到可执行文件，`./build/calculator` 就可以运行。
